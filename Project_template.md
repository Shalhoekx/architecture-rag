# Задание 1

# 1. Сравнение LLM-моделей.

## 1.1 Качество ответов
###    **Облачные модели:**
        Выше качество ответов
        Более точное следование инструкциям
        Большая база знаний
        Хорошо работает со сложными запросами
###    **Локальные модели:**
        Среднее качество ответов
        Ограниченный конекст
        Для специфических задач могут потребоваться тонкие настройки
        Хороши для узкопрофильных задач после дообучения

## 1.2 Скорость работы
###   **Облачные модели:**
        Высокая скорость
        Минимальные задержки
        Стабильная производительность
        Необходимость интернет подключения
###   **Локальные модели:**
        Зависимость от железа (GPU/CPU) - большие требования к RAM
        Отсутствуют сетевые задержки

## 1.3 Стоимость владения и использования
###    **Облачные модели**
    + Небольшие первоначальные затраты
    + Гибкое масштабирование
    + Оплата только при использовании
    - Цены могут изменяться
    - Доп. расходы при больших объёмах
    - При большом кол-во запросов может быть дорого

**Пример цен:**
- GPT-4: ~ $0.03/1K токенов 
- GPT-3.5 Turbo: ~ $0.0015/1K токенов   

###   **Локальные модели:**
    + Нет платы за использование
    + Предсказуемые расходы (если резко вырастет кол-во запросов или объёмов, это не приведёт к огромным счетам)
    + Экономия при больших объёмах
    - Высокие первоначальные затраты (настройка, выделение железа, оборудование, инфраструктура)
    - Амортизация оборудования и затраты на обслуживание

**Примерные затраты на оборудование:**
- Средний уровень: $2000-5000 за GPU
- Enterprise уровень: $10000+

## 1.4 Удобство и простота развёртывания

### **Облачные модели**
    + Простая интеграция через API
    + Готовые SDK и обилие документации
    + Автообновление моделей
    + Высокая доступность

###   **Локальные модели:**
    + Полный контроль и кастомизация
    + Изолированная (оффлайн) работа
    - Сложная настройка окружения
    - Требует наличия компетенций
    - Самостоятельное обслуживание

# 3. Сравнение векторных баз данных: ChromaDB vs FAISS

## 3.1 Скорость поиска и индексации
### **FAISS (Facebook AI Similarity Search)**

Производительность FAISS:

 + Экстремальная скорость поиска (оптимизированная C++ реализация)
 + Поддержка GPU (до 50x ускорение)
 + Эффективные алгоритмы сжатия (PQ, SQ)
 + Пакетный поиск с высокой пропускной способностью

Бенчмарки:
    Поиск 10NN в 1M векторов (384-dim): ~1-5 мс на CPU
    На GPU: ~0.1-1 мс на запрос
    Индексация: быстрая для простых индексов, медленнее для сжатых

### **ChromaDB**

Производительность ChromaDB:
 + Хорошая скорость (использует HNSW под капотом)
 - Медленнее FAISS на 20-50%
 + Оптимизирована для работы с метаданными
 - Задержки из-за overhead базы данных

Сравнение скорости:

FAISS: Лидер по чистой скорости
ChromaDB: Удобство в ущерб максимальной производительности

## 3.2 Сложность внедрения и поддержки

### **FAISS (Facebook AI Similarity Search)**

 + Полный контроль над производительностью
 + Гибкая настройка под конкретные задачи
 - Высокий порог входа (требует понимания алгоритмов)
 - Ручное управление сериализацией
 - Нет встроенной работы с метаданными
 - Требует самостоятельной оркестрации

### **ChromaDB**

 + Низкий порог входа (интуитивный API)
 + Встроенная персистентность
 + Автоматическое управление индексами
 + Готовая работа с метаданными и документами

## 3.3 Удобство в работе

### **FAISS (Facebook AI Similarity Search)**

 - Только векторный поиск (без метаданных из коробки)
 - Нет встроенной работы с текстами
 - Отсутствует REST API
 - Требует самостоятельной реализации дополнительного функционала

### **ChromaDB**
 + Встроенная фильтрация по метаданным
 + Работа напрямую с текстами (автоматическое эмбеддинг)
 + REST API и клиенты для разных языков
 + Встроенная аутентификация и авторизация

## 3.4 Стоимость владения

### **FAISS (Facebook AI Similarity Search)**
 + Нулевая стоимость лицензии (MIT License)
 + Эффективное использование ресурсов
 - требует серверов для размещения
 - Затраты на разработку и поддержку

### **ChromaDB**
 + Бесплатная open-source версия
 + Меньше затрат на разработку
 - Cloud версия: $20-500/мес (в зависимости от объема)
 - Зависимость от провайдера (в cloud)
